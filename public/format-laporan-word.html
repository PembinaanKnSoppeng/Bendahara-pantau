PERANCANGAN BASIS DATA & ALUR SISTEM (DATA FLOW)

Sistem Informasi Monitoring Tunjangan Kinerja & Uang Makan (SIMANTU) - Kejaksaan Negeri Soppeng

I. ARSITEKTUR STRUKTUR BASIS DATA

Basis data SIMANTU dibangun di atas sistem manajemen basis data relasional PostgreSQL yang di-host secara cloud pada platform Supabase. Arsitektur data mengadopsi prinsip Single-State Synchronization dan Audit Trail Logging, di mana status tahapan terkini dikelola melalui entitas tunggal (*singleton*) untuk memaksimalkan performa pembacaan data, sementara riwayat historis dicatat pada entitas arsip terpisah.

A. Diagram Konseptual Relasi Entitas (ERD)

TABEL OPERASIONAL REALTIME (SINGLETON)
• status_tukin_global (id = 1, periode, current_step, estimasi, catatan, is_rejected, updated_at)
• status_uang_makan_global (id = 1, periode, current_step, estimasi, catatan, is_rejected, updated_at)
⬌
TABEL HISTORIS & EVALUASI
• arsip_pencairan (id, periode, jenis, tanggal_cair)
• rating_kepuasan (id, periode, jenis, rating, created_at)
• auth.users (id, email, encrypted_password)

*Catatan Relasi: Saat proses mencapai Tahap 8 (SP2D Terbit) dan direset untuk bulan baru, data periode disalin dari status operasional ke arsip_pencairan. Respon survei kepuasan pegawai ditampung ke rating_kepuasan berdasar atribut periode dan jenis hak keuangan.

II. SPESIFIKASI DAN STRUKTUR TABEL BASIS DATA (KAMUS DATA)

1. Tabel: status_tukin_global

Menyimpan data pelacakan tahapan aktif pencairan Tunjangan Kinerja (Tukin) yang sedang berjalan saat ini.

No Nama Kolom Tipe Data Kunci / Index Fungsi & Aturan Bisnis
1 id BIGINT PRIMARY KEY Record tunggal konstan bernilai 1 (Singleton pattern).
2 periode TEXT - Nama bulan & tahun pencairan (contoh: "April 2026").
3 current_step INTEGER - Posisi tahapan aktif (rentang nilai integer 1 s/d 8).
4 estimasi TEXT - Estimasi waktu penyelesaian (contoh: "1-2 Hari Kerja").
5 catatan TEXT - Papan pengumuman bendahara atau instruksi berkas.
6 is_rejected BOOLEAN - Penanda berkas ditolak KPPN (True = Ditolak / Perbaikan).
7 updated_at TIMESTAMPTZ - Waktu dan tanggal pembaruan data terakhir.

2. Tabel: status_uang_makan_global

Menyimpan data pelacakan tahapan aktif pencairan Uang Makan bulanan pegawai.

No Nama Kolom Tipe Data Kunci / Index Fungsi & Aturan Bisnis
1 id BIGINT PRIMARY KEY Record tunggal konstan bernilai 1 (Singleton pattern).
2 periode TEXT - Nama bulan uang makan (contoh: "Maret 2026").
3 current_step INTEGER - Posisi tahapan aktif berjalan (nilai 1 s/d 8).
4 estimasi TEXT - Target durasi tahapan berjalan.
5 catatan TEXT - Pengumuman atau informasi resmi dari bendahara.
6 is_rejected BOOLEAN - Status penolakan berkas KPPN (True = Perbaikan).
7 updated_at TIMESTAMPTZ - Waktu pembaruan data sinkronisasi terakhir.

3. Tabel: arsip_pencairan

Menyimpan catatan rekam jejak historis periode anggaran yang telah sukses diterbitkan SP2D-nya.

No Nama Kolom Tipe Data Kunci / Index Fungsi & Aturan Bisnis
1 id BIGSERIAL PRIMARY KEY ID unik riwayat auto-increment.
2 periode TEXT - Bulan/Tahun yang telah tuntas terbit SP2D.
3 jenis TEXT - Kategori hak keuangan: 'Tukin' atau 'Uang Makan'.
4 tanggal_cair TIMESTAMPTZ - Waktu resmi pencairan/arsip dibukukan (default now()).

4. Tabel: rating_kepuasan

Menampung data hasil survei evaluasi indeks kepuasan pegawai secara mandiri dan anonim.

No Nama Kolom Tipe Data Kunci / Index Fungsi & Aturan Bisnis
1 id BIGSERIAL PRIMARY KEY ID evaluasi responden auto-increment.
2 periode TEXT - Periode pencairan yang dievaluasi.
3 jenis TEXT - Kategori layanan: 'Tukin' atau 'Uang Makan'.
4 rating INTEGER - Skor kepuasan berupa nilai bintang 1 sampai 5.
5 created_at TIMESTAMPTZ - Waktu saat formulir evaluasi dikirim oleh pegawai.

B. Skrip DDL SQL Pembuatan Struktur Tabel (PostgreSQL)

-- 1. TABEL STATUS TUKIN GLOBAL
CREATE TABLE IF NOT EXISTS public.status_tukin_global (
    id BIGINT PRIMARY KEY DEFAULT 1,
    periode TEXT NOT NULL DEFAULT 'Bulan Berjalan',
    current_step INTEGER NOT NULL DEFAULT 1 CHECK (current_step BETWEEN 1 AND 8),
    estimasi TEXT DEFAULT 'Tahap Awal',
    catatan TEXT DEFAULT '-',
    is_rejected BOOLEAN NOT NULL DEFAULT false,
    updated_at TIMESTAMPTZ DEFAULT now()
);

-- 2. TABEL STATUS UANG MAKAN GLOBAL
CREATE TABLE IF NOT EXISTS public.status_uang_makan_global (
    id BIGINT PRIMARY KEY DEFAULT 1,
    periode TEXT NOT NULL DEFAULT 'Bulan Berjalan',
    current_step INTEGER NOT NULL DEFAULT 1 CHECK (current_step BETWEEN 1 AND 8),
    estimasi TEXT DEFAULT 'Tahap Awal',
    catatan TEXT DEFAULT '-',
    is_rejected BOOLEAN NOT NULL DEFAULT false,
    updated_at TIMESTAMPTZ DEFAULT now()
);

-- 3. TABEL ARSIP PENCAIRAN
CREATE TABLE IF NOT EXISTS public.arsip_pencairan (
    id BIGSERIAL PRIMARY KEY,
    periode TEXT NOT NULL,
    jenis TEXT NOT NULL CHECK (jenis IN ('Tukin', 'Uang Makan')),
    tanggal_cair TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 4. TABEL RATING KEPUASAN
CREATE TABLE IF NOT EXISTS public.rating_kepuasan (
    id BIGSERIAL PRIMARY KEY,
    periode TEXT NOT NULL,
    jenis TEXT NOT NULL CHECK (jenis IN ('Tukin', 'Uang Makan')),
    rating INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

III. DIAGRAM ALUR DATA SISTEM (DATA FLOW)

1. Alur Transaksi Pembaruan Data Realtime (End-to-End Flow)

[1] AKSI ADMIN
Bendahara login & klik Lanjut Tahap di Command Center
 ➔
[2] DATABASE UPDATE
Kueri UPDATE current_step & updated_at dieksekusi di tabel
 ➔
[3] REALTIME CDC
Supabase memancarkan event perubahan via WebSocket Channel
 ➔
[4] CLIENT UPDATE
Layar ponsel pegawai berubah seketika tanpa perlu me-refresh halaman

2. Alur 8 Tahapan Siklus Pencairan Anggaran

Tahapan pencairan pada kolom current_step memetakan standar operasional prosedur KPPN:

Tahap Nama Tahapan Aktor / Unit Kerja Uraian Alur & Efek Data
Step 1 Rekapitulasi Absensi Urusan Kepegawaian Merekap data kehadiran pegawai dan perhitungan pemotongan hari kerja.
Step 2 Pengesahan Rekap Pimpinan Satker Verifikasi dan pengesahan surat rekapitulasi oleh pimpinan hierarki.
Step 3 Perhitungan Nominal Bendahara Pengeluaran Penghitungan nominal kotor, potongan PPh/BPJS, dan nominal bersih hak keuangan.
Step 4 Gaji Web KPPN Aplikasi Kemenkeu Penginputan dan sinkronisasi data nominatif ke portal Gaji Web KPPN.
Step 5 Validasi SAKTI Aplikasi SAKTI Satker Pengecekan pagu anggaran dan pencetakan Surat Permintaan Pembayaran (SPP).
Step 6 Pengajuan SPM Pejabat PPSPM Penerbitan Surat Perintah Membayar (SPM) dan pengiriman digital ke KPPN.
Step 7 Verifikasi KPPN Petugas FO / KPPN Pengujian berkas oleh KPPN. Jika ditolak, status berubah menjadi Revisi SPM.
Step 8 Penerbitan SP2D (Cair) KPPN & Bank Persepsi Surat Perintah Pencairan Dana terbit; dana ditransfer langsung ke rekening pegawai.

3. Alur Penanganan Berkas Ditolak / Revisi KPPN (Exception Flow)

Langkah 1: Verifikasi KPPN (Step 7) Mengalami Kendala

Apabila terdapat kesalahan data pada pengajuan SPM, KPPN menerbitkan penolakan / instruksi revisi.

Langkah 2: Bendahara Mengaktifkan Status Penolakan

Bendahara menekan tombol Tolak & Revisi (→ Step 6) pada panel admin. Basis data memperbarui record: current_step = 6 dan is_rejected = true.

Langkah 3: Layar Pegawai Menampilkan Indikator Perbaikan Berkas

Tampilan aplikasi di seluruh ponsel pegawai otomatis berubah warna menjadi merah dengan label "Perbaikan Berkas" dan catatan revisi, sehingga pegawai memahami penyebab keterlambatan secara transparan.

Langkah 4: Pengajuan Ulang SPM

Setelah berkas diperbaiki, bendahara memajukan kembali status ke Step 7, dan flag is_rejected otomatis kembali bernilai false.

4. Alur Pengarsipan & Reset Siklus Baru (Cycle Closure Flow)

Fase A: Pencairan Berhasil & Formulir Evaluasi (Step 8)

Saat SP2D terbit (Step 8), aplikasi pegawai memicu animasi selebrasi (confetti) dan membuka widget rating kepuasan (1 s/d 5 bintang) yang tersimpan di tabel rating_kepuasan.

Fase B: Pengarsipan Riwayat Otomatis

Ketika memasuki bulan baru, Bendahara menekan tombol Arsipkan & Reset. Sistem mengeksekusi penyalinan data periode yang telah sukses cair ke dalam tabel arsip_pencairan.

Fase C: Reset Status Operasional

Data pada status_tukin_global direset kembali ke current_step = 1, is_rejected = false, estimasi disetel ke "Tahap Awal", dan siap digunakan untuk memantau periode anggaran yang baru.
